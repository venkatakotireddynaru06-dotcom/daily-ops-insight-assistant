# Frontline Interview Guide (30 min)

Use this with a real person if you can (friend with a part-time job in hotels, trains, theme parks, retail).
Their answers replace the assumptions in `requirements.md` and `evaluate.py` (`MANUAL_MIN_PER_WEEK`).

1. Walk me through the last report or spreadsheet you prepared. Which files, what steps?
2. How long does it take, and how often? What is the most annoying step?
3. What decisions do you make from those numbers (staffing, ordering, schedules)?
4. When numbers look odd, what do you do? Who do you ask?
5. What would a "good" tool do for you? What would make you stop using it?
6. What data can you not share, or that must stay inside the company?
7. If I show you a draft next week, what would you want to see first?

**Write up:** one page: pain points, time spent, decision supported, constraints, quotes.

# Interview talking points (JD mapping)
- **Problem first:** "I started from a frontline reporting pain point, not from a model."
- **Small-scale pilot:** one report, one forecast, measurable targets set up front.
- **Honest evaluation:** model beat a same-weekday baseline by 35-66% MAPE on a held-out 90 days; the numbers are on synthetic data, so I treat them as proof of method.
- **AI used responsibly:** the agent only answers from computed tools and says when a gap is unexplained.
- **Security awareness:** aggregates only, no personal data, API key via environment.
- **What I'd do next:** real data + frontline feedback loop, weather feed, authentication, rollout plan.
